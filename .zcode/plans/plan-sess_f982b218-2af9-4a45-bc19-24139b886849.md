# 上传书籍 → 书库功能

## Context

阅读站（Next.js 16 + Rust axum + Postgres + Dexie）目前没有任何上传/文件解析代码。用户手上有《诡秘之主》的 2 个 TXT（约 3M 字，编码不同）、普通版 EPUB、插图版 EPUB（约 8MB 图片）、MOBI（17MB，PalmDB 格式），希望：上传后自动识别 → 自动分章 → 提取元数据（书名/作者/简介/封面）→ 形成书库中的书，并用现有连续滚动阅读器阅读。

## 架构决策

- **解析在浏览器端（TS）**：zip/xml/html/编码解码浏览器原生能力最全（DOMParser、TextDecoder('gbk')）；TS+vitest 迭代快；不引入 Rust 的 zip/xml/epub/mobi crates（均不成熟）。解析完以 JSON 一次性上传入库。
- **存储在服务端书库（Postgres）**：用户明确说「形成一本在书库里的书」；刚做过 LAN 支持，手机等设备也应能读；与现有书源书阅读链路最统一。上传/阅读需要 DB 在运行（与现有 /books 行为一致，DB 不可用时返回 503）。
- **插图支持**：段落字符串以 `data:image/…` 开头 → 阅读器渲染 `<img>`（paragraphs: string[] 模型不变）。
- **本地书合成 URL 方案**：章节 URL 用 `local://<idx>`，TOC/正文响应与 explore/toc、explore/content 完全同形，阅读器改动最小。

## 后端（Rust，apps/api）

1. **新迁移** `apps/api/migrations/0002_local_books.sql`
   - `local_books(id UUID PK, title, author, description, cover_url TEXT /*data-URI*/, format TEXT, chapter_count INT, text_hash TEXT UNIQUE, created_at, updated_at)`
   - `local_chapters(id BIGSERIAL PK, book_id UUID FK→local_books ON DELETE CASCADE, idx INT, title TEXT, paragraphs JSONB, UNIQUE(book_id, idx))`
2. **新路由** `apps/api/crates/server/src/routes/local_books.rs`（handler 风格照抄 books.rs：`ensure_db` + `AppError` + sqlx tuple query）
   - `POST /api/v1/local-books`：body `{title, author, description?, cover_data?, format, text_hash, chapters:[{title, paragraphs:string[]}]}`；text_hash 已存在则返回已有书 + `duplicate:true`；单事务插入；返回 `LocalBookRow`。该路由单独 `.layer(DefaultBodyLimit::max(96_000_000))`（axum 默认 2MB 拒 20MB 全书）
   - `GET /api/v1/local-books`：书库列表
   - `GET /api/v1/local-books/{id}/toc`：`{chapters:[{title, url:"local://<idx>"}]}`
   - `GET /api/v1/local-books/{id}/content?url=local://<idx>`：`{paragraphs, hashes}`（hashes 用 domain 的 simhash，与 explore/content 同算法）
3. `routes/mod.rs` 注册 4 条路由。

## 前端（apps/web）

1. **解析器** `apps/web/src/lib/import/`（新增 `jszip` 依赖；测试用 `happy-dom` devDep + `// @vitest-environment happy-dom`）
   - `types.ts`：`ParsedBook {title, author, description, coverData, format, textHash, chapters:[{title, paragraphs:string[]}]}`
   - `chapters.ts`：分章正则（`第[一二三…零〇0-9]+章`、`部/卷`、`序章/楔子/引子/尾声/终章/番外`），标题行长度上限防误判；卷/部标题并入下一章首段（TOC 保持扁平，不改 schema）
   - `txt.ts`：BOM → UTF-8 fatal 解码 → 失败回退 GBK/Big5（TextDecoder）；文首「书名：/作者：」提取元数据，否则文件名《X》作者：Y 兜底
   - `epub.ts`：JSZip → container.xml → OPF → spine + nav/NCX 取章题；DOMParser 抽段落（script/style 剔除、img → data-URI 嵌入段落流）；封面（cover-image properties / meta[name=cover]）→ canvas 缩至 ≤400px JPEG（失败退原图）
   - `mobi.ts`：PDB 记录表 + record0（PalmDOC/MOBI/EXTH 头）→ 文本记录 PalmDOC LZ77 解压（含 trailing bytes 裁剪）→ 拼 HTML 后复用 epub 的 html→段落逻辑 → 章节正则兜底切分；EXTH 100/503/201 → 作者/简介/封面；压缩类型 17480（HUFF/CDIC）或纯 KF8 抛清晰错误「请转 EPUB/TXT 后重试」
   - `index.ts`：`importFiles(files, onProgress)` 按扩展名分派，逐文件回调 解析中→上传中→完成/失败
2. **api.ts**：`uploadLocalBook / listLocalBooks / localToc / localContent` 四个方法（request() 封装复用）
3. **书架页** `apps/web/src/app/shelf/page.tsx`
   - header 加「导入书籍」→ `components/import/import-dialog.tsx`：拖拽+多选（.epub/.mobi/.txt/.azw3）、逐文件状态行、成功自动加入书架
   - 新增「书库（本地上传）」区块：列出 GET /local-books，「加入书架」按钮 → 写 Dexie ShelfItem `{bookId, sourceId: "local:<id>", bookUrl: "local://book", coverUrl}`（仿 explore 页加入书架 mutation）
4. **阅读链路最小分支**（`sourceId` 以 `local:` 开头时）：
   - `read/[bookId]/page.tsx` fetchToc：→ `api.localToc(id)`，否则走原 api.toc；进度恢复/目录抽屉/handleActiveIndex 零改动（`local://<idx>` 可被 findIndex 正常匹配）
   - `lib/reader/useReader.ts` loadChapter：→ `api.localContent({bookId, url})`（响应同形，照旧本地补 hash）
   - `components/reader/continuous-reader.tsx:371`：段落 `data:image/` 开头 → 渲染 `<img>`（无缩进、max-w-full）
5. **去重**：textHash 用 WebCrypto SHA-256（规范化后段落 join），服务端 UNIQUE；重复上传返回已有书，前端提示并直接入书架。
